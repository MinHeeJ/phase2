# UI Contract 느슨한 점검

## 범위와 판단 기준

- `.aiops-spec/ui-design.md`의 사용자 기능 계약을 현재 `frontend/src` 및 렌더 기반 시험과 비교했다. ASCII 위치·간격·컬럼 순서는 수정 대상으로 삼지 않았다.
- 읽기 전용 명세·backend·API/persistence는 변경하지 않았다. 모든 미적용 항목을 실패시키는 게이트를 추가하지 않았다.
- 인계 지도 버전/SHA-256/task ID는 제공된 값 그대로 미지정이다. `.aiops-spec/code-context/implementation-map.json`은 없으며 같은 디렉터리 검색에서도 발견되지 않았다. 추정 지도를 생성하지 않았다.
- `confirmations.json`, `output-contract.json`, `spec-review-acceptance.json`을 확인했다. 기존 추천인 단일 응답 봉투, 무인증/항상 허용, 전체 코드 수집, 대응 행별 저장/취소, 전체 월마감 조회를 유지했다. 이번 수정에 새 사람 선택은 필요하지 않아 outbox confirmations는 빈 배열이다.

## 보강 내용

- `CodesTab.tsx`: `[i].sort_seq`, `[i].aply_bgn_dt`를 실제 입력 name과 연결. 해당 필드 오류·접근성 설명·focus 및 수정 후 재저장을 지원한다. 기존 식별값이나 PUT 형태는 변경하지 않는다.
- `ParamsTab.tsx`: 서버 `field=month` 오류를 적용월 아래 표시하고 입력과 연결한다. 월 수정 시 지난 오류를 해제하며 창/값을 보존한다. 기존 서버 계약은 단수 `field`이며 임의 `fields` 배열을 도입하지 않는다.
- `ExcelMapsTab.tsx`: 신규 대응 메모를 TextInput의 기존 multiline 기능으로 표시한다. 요청 필드와 길이 제한은 유지한다.
- `CodeHistoryTab`: 초기화가 자동 조회·페이지 초기화를 하지 않고 입력 조건만 해제한다. 조회/Enter가 실제 결과를 갱신한다.

## 남은 gap / 이번에 완전 적용으로 선언하지 않는 사항

- 그룹 전환은 현재 선택을 바꾼 뒤 새 CodeEditor를 마운트한다. 새 그룹 조회 실패 시 이전 그룹 draft를 복원하는 흐름(ui-design.md:126)은 별도 상태 보존 보강이 필요하다. 이번 작은 필드/폼 수정에서 구조를 바꾸지 않았다.
- 그룹 추가 창은 다른 하위 탭에서도 열리며 취소 후 기존 하위 탭에 남는다. 문서의 코드 탭 복귀와 차이가 있다. 다른 탭 draft를 버리지 않는 보호 흐름을 함께 정리해야 하므로 강제 전환은 추가하지 않았다.
- 대응 표의 서버 메모 오류는 여러 행의 동일 name에 연결될 수 있고 주/보조·사용 오류의 행별 표시도 충분하지 않다. 변경 행 ID별 오류 상태는 후속 보강 대상으로 남긴다.
- 작업창 쓰기 결과 불명 시 onSaved 재조회가 실행된다. 특히 기준값은 조회 이후 닫힘 없이 적용이력이 바뀔 수 있다. 이번 시험은 명시적 400 오류에서 창/값 보존을 확인한 것이며 모든 연결 단절 시나리오 완료를 뜻하지 않는다.
- 기존 확인 기록은 추천 선택 상태이며 개별 사람 승인으로 격상하지 않았다. 단일 봉투/미사용 securitySchemes 등 읽기 전용 OpenAPI 정합성은 기존 계약 소유자 gap으로 남는다.
- 실제 DB/API·실브라우저 viewport/시각 비교는 이번 범위에서 실행하지 않았다. jsdom 렌더 시험을 실제 서버 인수나 픽셀 검증으로 대신하지 않는다.

## 검증

- `npm test -- --run`: Vitest + jsdom 전체 10개 파일, 233개 시험 통과(신규 렌더 시험 5개 포함).
- `npm run build`: TypeScript 검사 및 Vite production build 성공.
- 신규 `tests/UiContract.test.tsx`는 컴포넌트를 렌더해 실제 입력/오류 연결/focus/재저장/textarea 개행 payload/초기화 후 Enter를 시험한다. 소스 파일 읽기·raw import·문자열 소스 비교는 사용하지 않는다.
- 역할 구분은 현재 명세상 존재하지 않는다. 기존 무인증 메뉴/버튼 렌더 및 SYSTEM/BIZ 제한 시험을 유지했으며 가짜 ADMIN/USER 정책은 추가하지 않았다.
