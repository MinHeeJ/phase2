# UI Contract 느슨한 점검 결과

## 범위와 근거

- `.aiops-spec/ui-design.md`의 사용자 동작 계약과 현재 frontend 소스를 비교했다. ASCII 위치·간격·컬럼 순서는 수정 기준으로 삼지 않았다.
- 명세·code-context 사본은 변경하지 않았다. `.aiops-spec/code-context/implementation-map.json`은 조회와 파일 검색 모두에서 발견되지 않았다. 지도 버전/해시/task ID를 임의 생성하지 않았다.
- `confirmations.json`의 기존 추천 해석을 유지한다. 대응은 명시적 저장/취소와 변경된 허용 필드만 PATCH, 마감 범위는 기존 GET의 전체 달력 범위, UI-22는 메뉴를 추가하지 않는 직접 진입 자리 화면이다. provisional 추천을 사람 승인으로 간주하지 않는다.
- 신규 API, 응답 필드, DB/persistence, 역할·로그인 또는 업무 화면은 추가하지 않았다.

## 화면별 체크리스트와 관찰

공통 메뉴 경로는 getMenus의 실제 묶음/leaf 이름을 쓴다. 아래 공통 규칙은 해당 모든 route에 적용된다.

| 화면/region | 사용자 목적·레이아웃 영역 | CTA·입력·payload | 상태·제약·성공 동작 |
| --- | --- | --- | --- |
| YEAR: /UI-01, /UI-03, /UI-04, /UI-05, /UI-10, /UI-11, /UI-12, /UI-13, /UI-17, /UI-21, /UI-28 | 제목 → 기간 → 자리 안내 | 별·이전/다음 연도, 업무 mutation 없음 | 화면별 기간 유지, mobile=false는 PC 안내, 업무 편집 없음 |
| YEAR_CUM: /UI-07, /UI-08, /UI-09, /UI-18 | 제목 → 연도/누계월 → 자리 안내 | 별·연도 이동·누계월 선택, 업무 payload 없음 | 선택월과 누계 문구 연동, 기간 상태 유지 |
| MONTH: /UI-14, /UI-19, /UI-20 | 제목 → 조회월/마감 띠 → 자리 안내 | 별·조회월/이전·다음 월, 기존 getMonthClose만 사용 | CLOSED/OPEN 구분, 조회 실패 시 선택 보존·재시도, mobile=false PC 안내 |
| NONE: /UI-16, /UI-22, /UI-23, /UI-24, /UI-25 | 제목 → 자리 안내 | 기간/업무 입력 없음; /UI-22는 로그인 아님 | /는 /UI-16 이동, 메뉴/직접 진입 유지, 모바일 제약 재사용 |
| /UI-27 코드 | 네 하위 탭 → 그룹 rail/코드 표 | BIZ만 추가, 기존 코드 readonly, SYSTEM 이름·순서만 편집; 전체 페이지 확보 후 그룹 PUT | 미저장 그룹/하위 탭 이동 확인, 취소 복원, 저장 후 같은 그룹 재조회, 지정 성공 메시지 |
| /UI-27 그룹 추가 창 | 식별/이름 → 선택 추가값 이름 → 작업 버튼 | create 전용 ID/이름/attr 이름; type/order/use는 서버 소유 | 길이/필수·pending·실패 입력 유지·성공 닫기/목록 재조회 |
| /UI-27 대응 | 전체 폭 표 → 선택 행 편집 / 추가 작업창 | 기존 표기·대상 불변; PATCH는 변경된 역할/메모/사용만; create는 그룹별 활성 옵션과 주/보조 명시 선택 | 미저장 보호, 필드 오류, 저장 후 같은 페이지 재조회, 업로드/삭제 없음 |
| /UI-27 기준값 | 현재 표 → 선택 key 적용 이력 / 값 변경창 | 이름/단위/쓰는곳 readonly; 선택 key/month와 기존 종류의 값 한 필드만 PUT | 전체 마감 범위 실패 시 저장 금지; 마감월 이하 차단; 현재 목록/적용이력 재조회 |
| /UI-27 변경 이력 | 조건 → readonly 표 → 페이지 줄 | 그룹/초기화/조회·Enter, 기본50·20/50/100, mutation 없음 | 서버 total·페이지, NULL 변경자/구분 번역, 적용 이력과 별도 region |

모든 화면의 공통 shell은 API 메뉴·제목·breadcrumb, 즐겨찾기/최근 목록, 검색, 설정, 열린 탭과 로딩/빈 메뉴/조회 오류를 담당한다. 권한 계약은 누구나·무인증·Can=true다. 존재하지 않는 역할을 만들어 역할별 메뉴를 숨기지 않았으며 SYSTEM/BIZ와 모바일/마감 상태 제약을 구분해 검증했다.

## 이번에 수정한 명백한 drift

1. REQ-019/109: 코드 저장 시 native 검증만으로 끝나지 않도록 지정 필수 오류 표시와 첫 오류 focus를 추가했다. 공백만 있는 코드/이름도 빈 입력으로 판단하며, 다른 native 유효성 검사는 유지한다.
2. A-27-CANCEL / REQ-108: 코드 취소는 추가 이탈 확인 없이 마지막 저장본으로 복원한다. touched/서버 오류도 지운다. 그룹/하위 탭 이탈 확인은 유지했다.
3. REQ-058/119: 대응 편집의 map_role_cd/use_yn에도 서버 필드 오류를 표시한다. 사용 체크에 name을 연결해 기존 오류 focus가 동작하게 했다. 불변 표기/대상은 PATCH에 들어가지 않는다.
4. A-27-MAP-PATCH 및 쓰기 전 추가 확인 없음 계약: 대응 사용 변경도 기존 저장 버튼 한 번으로 확정한다. 추가된 2차 확인창만 제거했다.
5. REQ-124: 마지막 CLOSED가 9999-12라 허용월이 없으면 적용월 입력 자체도 비활성화한다. 저장 차단과 서버 재검증 계약은 유지한다.

## 남은 gap / 이번 범위에서 완료로 주장하지 않는 항목

- 셸의 `SharedWorkspace.open`은 미저장 화면에서도 메뉴/로고/열린 탭 이동을 바로 수행하고 숨겨진 탭의 draft를 보존한다. 명세 M1은 화면 이동에도 확인을 요구한다. 닫기 및 UI-27 그룹/하위 탭 전환은 이미 보호되지만 화면 이동 계약은 남아 있다. 이번 작은 보강에서는 탭 수명주기/브라우저 history 처리까지 재작성하지 않았다.
- M4의 로컬 필수 blur 메시지는 공통 입력의 일반 메시지를 사용한다. 명세의 엑셀 표기/대응 코드별 지정 문구까지는 이번에 변경하지 않았다.
- 이력 외 목록의 페이지 UI/default 정책 등 OQ와 기존 추천 해석 사이 차이는 그대로 남긴다. 승인되지 않은 API/schema 필드를 만들어 해소하지 않았다.
- 전체 메뉴 정본과 실제 DB/API 응답을 이번 작업에서 통합 검증하지 않았다. route 시험은 기존 API 대역을 통해 렌더링하는 회귀 시험이며 실제 배포/DB 전체 inventory 보증이 아니다.
- 브라우저 픽셀·반응형 실측, 실제 PostgreSQL rollback/기존 데이터 비소급은 이번 jsdom 시험으로 보증하지 않는다.
- implementation-map 부재로 task별 지도 대조는 할 수 없다. outbox에는 신규 사람 선택 사항이 없어 confirmations=[]를 기록한다. 위 gap은 작업 보고서이며 outbox에 넣지 않는다.

## 실행 검증

- 수정 전 UI27 렌더 회귀: 6 failed / 22 passed. 추가·변경한 동작 시험이 실제로 누락을 재현했다.
- 수정 후 `npm test -- --run --reporter=dot`: 12 test files, 188 tests passed.
- `npm run build`: TypeScript noEmit 및 Vite production build 성공.
- 환경은 `frontend/vite.config.ts`의 jsdom이다. 추가 시험은 컴포넌트를 렌더링하고 입력·버튼·오류·포커스·API 호출 payload를 관찰한다. 소스 파일 읽기/문자열 비교 또는 raw import 시험을 추가하지 않았다.
- React Router future-flag 및 실행 환경의 Undici experimental 경고는 있었으나 시험/빌드 실패는 없었다.
